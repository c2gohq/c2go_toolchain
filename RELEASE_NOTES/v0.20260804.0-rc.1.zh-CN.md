> **候选版本：**本版本用于评估和兼容性测试，尚未签名，也未达到生产可用状态。

C2Go Toolchain `v0.20260804.0-rc.1` 使用集中式编译期 toolchain contract
provider，替代每个生成包各自写死的未来 Go 版本上限。Schema v2 目标库无需
重新生成即可同时支持 Go 1.25.x 和 Go 1.26.x。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260804.0-rc.1/RELEASE_NOTES/v0.20260804.0-rc.1.md)

## 相比 v0.20260802.0-rc.1 的变化

- c2go-clang 现在生成 manifest schema v2，并记录两个互相独立的兼容轴：
  `c2go_abi_epoch` 和 `go_toolchain_contract_epoch`。
- Schema v2 保留最低 Go 版本和仅供记录的验证快照，但不再为每个目标产物设置
  未来 Go 的编译上限。
- c2go-lto 会拒绝混合的 manifest 代际和不一致的契约，并对多个翻译单元的
  验证快照保守取交集。
- c2go-bind 对已发布的 schema v1 继续保留硬版本窗口；对 schema v2 则生成
  只有最低版本的 build tag 和双 epoch 编译期 anchor。
- c2go-libc 新增无依赖的 `c2goabi` provider。Go 1.25.x 与 Go 1.26.x 映射
  到 Go toolchain contract epoch 1；Go 1.27 及以后版本在新版 provider
  完成验证前默认拒绝。
- 未来兼容的 Go minor 版本只需升级 c2go-libc provider，已有 schema v2
  目标库的 `.go` 和 `.s` 均无需变化。
- Release workflow 会在每个原生目标 runner 上使用 Go 1.26 测试
  c2go-bind/goprobe 与 c2go-libc，并在上传前分别使用 Go 1.25 和 Go 1.26
  对打包后的 SDK 执行端到端 smoke test。

旧 schema v1 库继续保持原有 `max_go_version` 行为。它们需要重新生成一次才能
迁移到 provider 模式；新工具不会静默改变冻结产物的语义。

## 打 tag 前的验证

- c2go-clang 与 c2go-lto 重建成功，5 个 schema、多翻译单元和 archive
  重点契约测试全部通过。
- c2go-bind 测试和 vet 在 Go 1.25.9、Go 1.26.0 下通过，包括结构化 Go
  frame-accounting probe。
- c2go-libc 根包、`dl`、`selftest` 在 Darwin arm64 上分别使用 Go 1.25.9
  和 Go 1.26.0 原生通过。
- Linux amd64、Linux arm64、Windows amd64 的 c2go-libc 包在 Go 1.26.0
  下交叉编译通过。
- Schema v2 SQLite 消费者独立使用 Go 1.25.9 和 Go 1.26.0 测试通过；Go
  1.26 测试启用了 `GOGC=1` 与 `GODEBUG=invalidptr=1`。
- Go 1.27rc1 按预期被中央 provider 拒绝；显式的未验证 toolchain 测试 tag
  可以选择 epoch 1。
- 此次版本策略迁移没有改变 c2go-libc 或 SQLite 的生成汇编。

打 tag 后的 release workflow 会在四个受支持目标上重复原生验证。Workflow
仍在排队或运行时，不能据此宣称二进制产物已经发布完成。

## 已知限制与许可证

- 仅支持 C，不支持 C++ 和 32 位目标。
- 支持 Go 1.25.x 和 Go 1.26.x；Windows 的 POSIX 接口范围较小。
- C2Go 无法像 Go 编译器一样把发生逃逸的 C 栈局部变量提升到堆上；发布前必须把
  独立 `c2go-lto` 逃逸审计作为单独门禁。
- 接口和 ABI 细节仍处于 pre-1.0 阶段，后续可能修改。

本聚合包包含多个许可证边界。使用或再分发前必须保留并阅读根目录和
`licenses/` 中的授权记录。商业协议不能重新许可 LLVM、musl 或其他第三方代码。
