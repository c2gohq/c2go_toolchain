# C2Go Toolchain v0.20260809.0-rc.3

本候选版本取代 `v0.20260809.0-rc.2`；后者在打包前未通过 Windows 原生运行
门禁。rc.3 保留 rc.2 的 Linux ARM64 编译器修正，并修复 Windows managed
`glob` 自测的路径可移植性问题。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.3/RELEASE_NOTES/v0.20260809.0-rc.3.md)

## 相比 v0.20260809.0-rc.2 的变化

- managed `glob` 的 GC/ownership 夹具现在会把 Windows `%TEMP%` 提供的宿主
  路径规范化为正斜杠。生产 `glob` 仍保留 POSIX pattern 语义，包括反斜杠
  转义。
- 使用修正后的夹具重新生成了 namespaced 与 unprefixed Windows 自测汇编。
- 新增独立的 Windows 原生 contract workflow，将 root libc、mlib、目录、
  glob、同步、stdio、regex 和 search 分片运行，使问题能在创建发布标签前被
  准确归因。

rc.2 中的 AArch64 可变参数 ABI、拆分 GOT lowering、Linux/ARM64 重新生成
产物以及生成器安全门保持不变。

## 打标签前的验证

- Windows/AMD64 原生 runner 的全部 contract 分片通过，包括 namespaced
  managed glob 和完整的 unprefixed mlib 自测。
- 重新生成后，macOS/ARM64 在 `GOGC=1`、`GODEBUG=invalidptr=1` 下通过全部
  package 测试。
- Windows/AMD64 在本机可交叉编译和汇编全部 Go package。
- 锁定的组件 revision 与远端组件标签通过 release snapshot verifier。

聚合标签触发的 workflow 仍须完整通过，之后才能认为 GitHub Release 草稿和
下载资产可用。

## 已知限制与许可

- 仅支持 C；不支持 C++ 和 32 位目标。
- 支持 Go 1.25.x 和 Go 1.26.x；Windows 的 POSIX 功能面较小。
- C2Go 不能把发生逃逸的 C 栈局部变量提升到堆上；发布时仍需单独运行
  `c2go-lto` 逃逸审计。
- mlib 函数不能接收 root libc carrier，root libc 函数也不能接收 mlib
  carrier。
- 接口和 ABI 仍处于 pre-1.0 阶段，后续可能调整。

本聚合包包含多个许可证边界。使用或再分发前请保留并检查根目录及
`licenses/` 中的记录；商业协议不能改变 LLVM、musl 或其他第三方代码的许可。
