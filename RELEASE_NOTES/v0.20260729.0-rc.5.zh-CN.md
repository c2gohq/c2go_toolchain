## 相比 rc.4 的变化

- `c2go.h` 保持为编译器所有的 Clang resource header，安装在
  `lib/clang/<version>/include/c2go.h`，不再复制到顶层 `include/`。
- 顶层 `include/` 现在精确包含 Git 跟踪的 c2go-libc 公共 C 头文件。Clang
  resource headers 仍是独立且优先的搜索层。
- c2go-clang 的已安装 SDK 探测遵循这一归属边界，并已通过 Clang Driver
  测试套件覆盖。
- 压缩包校验要求 resource 目录中恰好存在一份 `c2go.h`，并拒绝顶层副本。
- 平台包内编译器仍名为 `c2go-clang`（Windows 为 `c2go-clang.exe`），GitHub
  Release 标题仍只使用协同版本号。

## 已安装 SDK 结构

```text
c2go-toolchain-v0.20260729.0-rc.5-<target>/
├── bin/                         c2go-clang、c2go-lto、c2go-bind
├── include/                     c2go-libc 公共 C 头文件
├── lib/clang/<version>/         Clang resource，包含 c2go.h
├── licenses/                    各组件及第三方授权记录
├── README.md
├── README.zh-CN.md
├── BUILD-INFO.json
├── toolchain.lock.json
└── LICENSE、NOTICE 等
```

平台 SDK 不包含仓库 checkout、测试、构建脚本或组件源码树。递归完整对应源码
作为独立资产发布。

使用时固定匹配的 Go runtime module：

```sh
go get github.com/c2gohq/c2go_libc@v0.20260729.0-rc.5
```

## 校验并开始使用

先验证 `SHA256SUMS`，再解压与宿主匹配的平台包，并将其 `bin/` 加入 `PATH`：

```sh
export C2GO_HOME="$PWD/c2go-toolchain-v0.20260729.0-rc.5-linux-amd64"
export PATH="$C2GO_HOME/bin:$PATH"

c2go-clang --version
c2go-lto --version
c2go-bind --version
```

target triple 和完整 C 到 Go 示例见压缩包内的中英文 README。

每个原生 release job 都会在上传前解压自己的平台包，验证精确的工具、头文件、
目录与许可文件集，在不额外传 `-I` 的情况下解析每个受支持公共头文件，并完整执行
已打包工具的“C -> Plan 9 汇编 -> Go package”流水线。

## 已知限制与许可证

- 仅支持 C，不支持 C++ 和 32 位目标。
- 仅支持 Go 1.25.x；Windows 的 POSIX 接口范围较小。
- 接口和 ABI 细节仍处于 pre-1.0 阶段，后续可能修改。
- 签名、公证、SBOM 发布以及全仓法律复核尚未完成。

本聚合包包含多个许可证边界。使用或再分发前必须保留并阅读根目录和
`licenses/` 中的授权记录。商业协议不能重新许可 LLVM、musl 或其他第三方代码。
