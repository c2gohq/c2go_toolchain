> **Release candidate:** this build is for evaluation and compatibility testing.
> It is unsigned and not production-ready.

C2Go Toolchain `v0.20260801.0-rc.1` makes LLVM bitcode objects the normal
multi-file build boundary and gives the Clang manifest sole ownership of the Go
package import path.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260801.0-rc.1/RELEASE_NOTES/v0.20260801.0-rc.1.zh-CN.md)

## Changes from v0.20260729.0-rc.5

- `c2go-clang -fc2go -c source.c -o source.o` now writes LLVM bitcode to the
  requested `.o` path by default. Neither `-emit-llvm` nor `-flto` is required.
- `c2go-lto` can be used as an `ar` replacement: `c2go-lto rcs libname.a
  one.o two.o` links the bitcode inputs and writes the Plan 9 assembly and
  manifest members consumed by `c2go-bind`.
- `-flto` and `-flto=thin` remain accepted for build-system compatibility; they
  are not a separate C2Go build mode.
- `-fc2go-package=<import-path>` is now the authoritative package identity.
  Same-package `c2go_linkname` targets become package-local symbols, while
  cross-package targets retain their full Go linker identity.
- `c2go-bind` no longer accepts the duplicate `--pkg` override. It reads the
  import path from the manifest; `--pkgname` remains available when the Go
  `package` clause differs from the import-path base.
- c2go-libc assembly was regenerated for all five supported target outputs with
  package-local calls and the updated binding workflow.
- Debug metadata remains available to the standalone escape audit and optional
  bitcode output, then is removed immediately before Plan 9 assembly emission
  to avoid unsupported DWARF streamer paths.

## Normal multi-file workflow

```sh
c2go-clang --target="$C2GO_TARGET" -std=c2go23 -fc2go \
  -fc2go-package=example.com/acme/mypkg -O2 -c one.c -o one.o
c2go-clang --target="$C2GO_TARGET" -std=c2go23 -fc2go \
  -fc2go-package=example.com/acme/mypkg -O2 -c two.c -o two.o
c2go-lto rcs libmypkg.a one.o two.o
c2go-bind --out=./mypkg libmypkg.a
```

The `.o` files above are LLVM bitcode despite their conventional object suffix.
Do not pass them to a native system linker or native `ar`.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x only; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- Interfaces and ABI details remain pre-1.0 and may change.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
