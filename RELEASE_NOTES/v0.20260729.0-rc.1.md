> **Release candidate:** this build is for evaluation, reproducibility checks,
> and compatibility testing. It is not a production-ready release.

This is the first coordinated C2Go Toolchain release candidate. It freezes the
compiler, binding generator, runtime compatibility layer, and nested musl fork
as one reviewable snapshot. The release tag identifies the coordinated
snapshot; the exact source revisions are recorded in `toolchain.lock.json` and
reproduced below.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260729.0-rc.1/RELEASE_NOTES/v0.20260729.0-rc.1.zh-CN.md)

## Highlights

- Provides the coordinated C-to-Go pipeline: C2Go Clang and `c2go-lto` emit
  Go-compatible Plan 9 assembly plus an export manifest, `c2go-bind` generates
  the Go package, and `c2go-libc` supplies the matching runtime interfaces.
- Packages native toolchains for Linux amd64, Linux arm64, Windows amd64, and
  macOS arm64.
- Targets Go 1.25.x and C2Go ABI epoch 1. Release builders use Go 1.25.9.
- Includes the current X86-64 and AArch64 C2Go lowering work, supported inline
  assembly handling, synthesized-libcall routing, and GC-safety corrections.
- Removes the obsolete runtime GC-mask lookup registry while retaining the
  generated Go-owned layout needed for pointer-carrying C globals.
- Includes tracked target-specific `c2go-libc` Go/assembly artifacts and the
  external native-call `dl` bridge.
- Ships a recursive corresponding-source archive, per-file SHA-256 sidecars,
  and a combined `SHA256SUMS` file.

## Verify and try the toolchain

Download the archive for the host together with `SHA256SUMS`, then verify it
before extraction. For example, on Linux:

```sh
sha256sum --check SHA256SUMS
tar -xzf c2go-toolchain-v0.20260729.0-rc.1-linux-amd64.tar.gz
export PATH="$PWD/c2go-toolchain-v0.20260729.0-rc.1-linux-amd64/bin:$PATH"

clang --version
c2go-lto --version
c2go-bind --version
```

The archive contains the matching c2go-libc source/runtime package and the
applicable release, license, and notice documents. Use the components as one
locked set.

## Release verification

The tagged release workflow:

- verifies that every public component tag resolves to the commit recorded in
  `toolchain.lock.json`;
- builds C2Go Clang, `c2go-lto`, and `c2go-bind` natively on all four packaged
  targets;
- runs the checked-in `c2go-bind` and `c2go-libc` Go tests on those builders;
- checks tool versions and the locked c2go-clang revision during packaging; and
- creates deterministic binary archives and a recursive source bundle.

These packaging checks do not turn the project into a production-certified C
implementation and do not replace the component repositories' complete LIT,
clean-checkout, provenance, or legal review gates.

## Known limitations

- C only; C++ is not supported.
- 64-bit X86 and AArch64 only; this release packages the four hosts listed
  above.
- Go 1.25.x only. Go 1.26 and later are intentionally rejected by this ABI
  line.
- `c2go-libc` is a compatibility layer for translated programs, not a drop-in
  host libc. Windows has a smaller POSIX surface, and 32-bit targets are not
  supported.
- Interfaces, manifests, and ABI details remain pre-1.0 and may change in a
  later coordinated snapshot.
- Signing, Apple notarization, Windows Authenticode, SBOM publication, and the
  repository-wide provenance/legal review are not yet complete.

Please report results with the release version, host OS/architecture, Go
version, input source, full command line, and a minimal reproducer.
