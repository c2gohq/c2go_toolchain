# C2Go Toolchain v0.20260809.0-rc.4

This candidate supersedes `v0.20260809.0-rc.3`, whose Linux/AMD64 builder
detected non-reproducible committed assembly before packaging. It retains the
Windows managed-glob and Linux ARM64 corrections from the preceding candidates
and makes C2Go libc generation independent of the host checkout path and host
operating system.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.4/RELEASE_NOTES/v0.20260809.0-rc.4.zh-CN.md)

## Changes from v0.20260809.0-rc.3

- libc and mlib generation now remap the source root to a stable relative path,
  preventing C `__FILE__` values in generated selftests from embedding a local
  checkout path.
- Darwin generation now pins the macOS 11 deployment target. An unversioned
  Darwin target previously inherited the local macOS version on a Darwin host
  but selected a different default on a Linux cross-generation host.
- The affected selftest assembly was regenerated without workstation-specific
  paths.

The production library assembly is otherwise unchanged from rc.3. The Windows
managed-glob portability fix, AArch64 variadic ABI and split-GOT corrections,
and generator safety gates remain in place.

## Validation before tagging

- Full regeneration is idempotent on macOS/ARM64.
- A clean Linux/AMD64 container using the pinned c2go-clang and c2go-bind
  revisions produces the exact same binary Git diff as macOS/ARM64.
- Native macOS/ARM64 and Linux/AMD64 pass all packages with `GOGC=1` and
  `GODEBUG=invalidptr=1`.
- Linux/ARM64 and Windows/AMD64 cross-compile and assemble every Go package.
- Native Windows/AMD64 passes every sharded contract job, including namespaced
  managed glob and the complete unprefixed mlib selftest.
- The locked component revisions and remote component tags pass the release
  snapshot verifier.

The tagged aggregate workflow must still complete before the draft and
downloadable assets are considered available.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x and Go 1.26.x are supported; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- mlib functions must not receive root-libc carriers, and root-libc functions
  must not receive mlib carriers.
- Interfaces and ABI details remain pre-1.0 and may change.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
agreement cannot relicense LLVM, musl, or other third-party code.
