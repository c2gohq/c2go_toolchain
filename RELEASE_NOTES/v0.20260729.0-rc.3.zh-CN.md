C2Go Toolchain `v0.20260729.0-rc.3` 修正了 rc.2 的平台包结构。
**请勿继续使用 rc.2 的二进制 SDK 压缩包：**其中错误包含开发源码树，同时遗漏
已安装的 c2go-libc 公共头文件树。递归完整的对应源码仍通过独立源码资产提供。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260729.0-rc.3/RELEASE_NOTES/v0.20260729.0-rc.3.md)

## 主要内容

- 每个平台包改为可整体搬移的已安装 SDK，只包含 `bin/`、`include/`、`lib/`、
  `licenses/` 和 release 元数据。
- 在顶层 `include/` 安装 `c2go.h` 与受版本控制的完整 c2go-libc 公共 C 头文件树；
  二进制 SDK 不再复制源码仓库、测试和构建脚本。
- C2Go Clang 在 `-fc2go` 模式自动发现 SDK 的 `include/` 与自身 Clang resource
  目录；普通 Clang 模式以及 `-nostdinc` 控制保持原有行为。
- 修复 `fcntl.h`，使其中使用 `off_t` 的声明能够独立解析。
- 每个原生平台包在上传前都会被重新解压，严格检查 SDK 结构，在不额外传 `-I`
  的情况下解析每个受支持的公共头文件，并完整执行“C -> Plan 9 汇编 -> 生成 Go
  package”测试。
- 递归完整对应源码继续作为独立 `-source` 资产发布，同时提供逐文件 SHA-256
  sidecar 与汇总 `SHA256SUMS`。

## 已安装 SDK 结构

```text
c2go-toolchain-v0.20260729.0-rc.3-<target>/
├── bin/                         clang、c2go-lto、c2go-bind
├── include/                     c2go.h 与 c2go-libc 公共 C 头文件
├── lib/clang/<version>/         Clang 运行资源
├── licenses/                    各组件及第三方授权记录
├── README.md                    英文 SDK 快速上手
├── README.zh-CN.md              中文 SDK 快速上手
├── BUILD-INFO.json
├── toolchain.lock.json
└── LICENSE、NOTICE 等
```

平台 SDK 有意不捆绑预编译 Go archive，也不复制 c2go-libc 源码 checkout。Go
archive 与精确 Go 版本、构建参数和依赖 build ID 绑定。使用者应固定匹配版本的
module：

```sh
go get github.com/c2gohq/c2go_libc@v0.20260729.0-rc.3
```

## 校验并开始使用

下载对应宿主的压缩包和 `SHA256SUMS`，解压前先校验。例如在 Linux amd64：

```sh
sha256sum --check SHA256SUMS
tar -xzf c2go-toolchain-v0.20260729.0-rc.3-linux-amd64.tar.gz
export C2GO_HOME="$PWD/c2go-toolchain-v0.20260729.0-rc.3-linux-amd64"
export PATH="$C2GO_HOME/bin:$PATH"

clang --version
c2go-lto --version
c2go-bind --version
```

target triple、匹配的 c2go-libc module 和完整 C 到 Go 快速上手步骤见压缩包内的
`README.md` 或 `README.zh-CN.md`。

## 发布验证

正式 tag 对应的 workflow 会：

- 校验远端组件 tag、锁定 revision、递归依赖和干净源码快照；
- 在 Linux amd64/arm64、Windows amd64 与 macOS arm64 上原生构建并测试
  C2Go Clang、`c2go-lto`、`c2go-bind` 和 c2go-libc；
- 生成确定性平台 SDK 与递归完整源码包；
- 拒绝平台包中的源码树、缺失或多余的安装头文件、缺失的许可记录以及错误的
  build 元数据；
- 解压每个压缩包，并在允许上传前通过公共头文件检查和完整已打包工具 smoke test。

这些检查不会把候选版自动变成经过生产认证的 C 实现，也不能替代完整的来源与
法律复核。

## 已知限制

- 仅支持 C，不支持 C++。
- 仅支持 64 位 X86 和 AArch64；本版本只打包上述四种宿主。
- 仅支持 Go 1.25.x；Go 1.26 及以后版本不在该 ABI 版本线内。
- `c2go-libc` 是供转换后程序使用的兼容层，不是宿主 libc 的直接替代品；
  Windows 的 POSIX 接口范围较小，也不支持 32 位目标。
- 接口、manifest 和 ABI 细节仍处于 pre-1.0 阶段，后续可能修改。
- 签名、Apple notarization、Windows Authenticode、SBOM 发布以及全仓来源/法律
  复核尚未完成。

反馈问题时请提供 release 版本、宿主 OS/架构、Go 版本、输入源码、完整命令行
和最小复现样例。
