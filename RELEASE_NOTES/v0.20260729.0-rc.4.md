[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260729.0-rc.4/RELEASE_NOTES/v0.20260729.0-rc.4.zh-CN.md)

## Changes from rc.3

- The packaged compiler is now named `c2go-clang` (`c2go-clang.exe` on
  Windows), making it explicit that this is the C2Go compiler rather than a
  drop-in replacement for the host `clang` command.
- `c2go.h` now has one canonical installed copy in top-level `include/`; the
  duplicate copy is removed from `lib/clang/<version>/include`.
- Clang resource headers and c2go-libc headers that intentionally share a
  standard name remain in their respective layers. They have different
  contents and responsibilities; the compiler resource layer delegates to the
  libc layer where required.
- GitHub Release titles use the bare coordinated version.
- Archive verification rejects the legacy `bin/clang` name, unexpected tools,
  and a duplicate resource-tree copy of `c2go.h`.

## Installed SDK layout

```text
c2go-toolchain-v0.20260729.0-rc.4-<target>/
├── bin/                         c2go-clang, c2go-lto, c2go-bind
├── include/                     c2go.h and c2go-libc public C headers
├── lib/clang/<version>/         Clang runtime resources
├── licenses/                    component and third-party license records
├── README.md
├── README.zh-CN.md
├── BUILD-INFO.json
├── toolchain.lock.json
└── LICENSE, NOTICE, ...
```

The platform SDK contains no repository checkout, test suite, build script, or
component source tree. Complete corresponding source is a separate asset.

Pin the matched Go runtime module:

```sh
go get github.com/c2gohq/c2go_libc@v0.20260729.0-rc.4
```

## Verify and start

Verify `SHA256SUMS`, extract the archive matching the host, and add its `bin/`
directory to `PATH`. For example:

```sh
export C2GO_HOME="$PWD/c2go-toolchain-v0.20260729.0-rc.4-linux-amd64"
export PATH="$C2GO_HOME/bin:$PATH"

c2go-clang --version
c2go-lto --version
c2go-bind --version
```

Read the English or Chinese README inside the archive for target triples and a
complete C-to-Go example.

Each native release job extracts its platform archive, verifies the exact tool,
header, layout, and license sets, parses every supported public header without
an extra `-I`, and executes the packaged C -> Plan 9 assembly -> Go package
pipeline before upload.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x only; Windows has a smaller POSIX surface.
- Interfaces and ABI details remain pre-1.0 and may change.
- Signing, notarization, SBOM publication, and repository-wide legal review are
  not complete.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
agreement cannot relicense LLVM, musl, or other third-party code.
