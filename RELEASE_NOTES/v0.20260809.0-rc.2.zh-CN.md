# C2Go Toolchain v0.20260809.0-rc.2

本候选版本取代未完成打包的 `rc.1`。它保留该版本引入的 managed libc 能力，
并修复原生 release runner 发现的两个 Linux ARM64 代码生成问题。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.2/RELEASE_NOTES/v0.20260809.0-rc.2.md)

## 相比 v0.20260809.0-rc.1 的变化

- 所有 AArch64 目标上的 C2Go 可变参数函数统一使用单个 `void *` 游标。Linux
  不再把原生五字段 AAPCS `va_list` 暴露给生成的 Go 声明和栈扫描信息。
- AArch64 Plan 9 printer 现在能在调度将 ELF GOT 的 `ADRP` 与 `LDR` 分开时
  保留符号地址，包括跨基本块的情况。这样不会再把
  `runtime.writeBarrier` 标志位的内容当成指针并解引用。
- 使用修正后的编译器重新生成了 root libc 与 mlib 的 Linux/ARM64 Go 和汇编
  产物。
- 两套 libc 生成器现在都会拒绝 ARM64 输出中不安全的裸
  `MOVD runtime·writeBarrier(SB)` 形式，使这类问题在发布阶段直接失败。

其他 managed libc API 与兼容规则均与 `v0.20260809.0-rc.1` 保持一致。

## 打标签前的验证

- clang 的可变参数 ABI 和拆分 GOT 两项定向回归测试通过。
- root libc 与 mlib 均能完整重新生成，并通过新增 ARM64 安全门。
- Linux/ARM64 与 macOS/ARM64 在 `GOGC=1`、
  `GODEBUG=invalidptr=1` 下通过全部 package 测试。
- Linux/AMD64 使用 Go 1.26 和相同 GC 压力设置，连续十个独立全量测试进程
  全部通过。
- Windows/AMD64 的所有 package 均可编译和汇编；打标签后的 workflow 是其
  原生 Windows 运行时门禁。

workflow 完成以前，不应将 GitHub Release 草稿及下载资产视为已经可用。

## 已知限制与许可

- 仅支持 C；不支持 C++ 和 32 位目标。
- 支持 Go 1.25.x 和 Go 1.26.x；Windows 的 POSIX 功能面较小。
- C2Go 不能把发生逃逸的 C 栈局部变量提升到堆上；发布时仍需单独运行
  `c2go-lto` 逃逸审计。
- mlib 函数不能接收 root libc carrier，root libc 函数也不能接收 mlib
  carrier。
- 接口和 ABI 仍处于 pre-1.0 阶段，后续可能调整。
