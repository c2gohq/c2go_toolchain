> **Release candidate:** this build is for evaluation and compatibility testing.
> It is unsigned and not production-ready.

C2Go Toolchain `v0.20260809.0-rc.1` introduces the first broad managed-libc
surface in `github.com/c2gohq/c2go_libc/mlib`. It lets translated C code keep
Go-managed pointers in precisely scanned C records without routing those
objects through the root libc package's process-wide handle tables.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.1/RELEASE_NOTES/v0.20260809.0-rc.1.zh-CN.md)

## Changes from v0.20260804.0-rc.1

- Added namespaced `mlib_*` APIs and opt-in `C2GO_MLIB_UNPREFIXED` source-name
  replacement for the implemented managed families.
- Added managed semaphore and pthread lifecycle/synchronization carriers;
  directory streams, `scandir`, `glob`, `nftw`/`ftw`; search trees, hash
  tables, and queues; managed POSIX regex; and the managed `FILE` surface,
  including standard, memory, cookie, wide, formatted, and process streams.
- Added GC-owned `strdup`, `strndup`, `wcsdup`, `asprintf`, `vasprintf`,
  `realpath`, and `getcwd` variants.
- Logical release operations now clear library-owned managed roots. When a C
  API receives an owning pointer by value, callers should also assign their
  final owner to `NULL` after close, destroy, or release.
- Kept stateless algorithms and Go-owned behavior cores shared. Allocation- or
  layout-sensitive C code is selectively instantiated for mlib; the complete
  musl library is not built twice.
- c2go-clang now emits concrete layouts for exported by-value C records, so Go
  declarations preserve argument size and placement instead of using an empty
  placeholder.
- c2go-bind now discovers imports for generated libc subpackages and direct
  top-level Go-package assembly references.
- The release workflow now regenerates both root libc and mlib on Linux/amd64
  with the pinned clang, c2go-lto, and c2go-bind, then rejects any difference
  from the committed `.go` and `.s` artifacts.

`mlib` is a selective managed surface, not a second complete libc. There is no
umbrella header: include the individual `<c2go/mlib/*.h>` families you use.
Ordinary `malloc`, `realloc`, and `free` are intentionally absent; allocate a
pointer-bearing managed record with typed `gc_malloc`, and use
`gc_malloc(NULL, size)` only for pointer-free storage. `iconv` remains root-only,
and `lsearch`/`lfind` remain suitable only for pointer-free elements.

## Validation before tagging

- Root libc and mlib regenerated identically for all five release targets with
  the pinned c2go-clang and c2go-bind.
- The focused c2go-clang by-value-record regression passed.
- All c2go-bind tests passed.
- All c2go-libc packages passed with `GOGC=1` and
  `GODEBUG=invalidptr=1`; all mlib packages also passed under the Go race
  detector on Darwin/arm64.

The tagged release workflow repeats native Go-contract and package validation
on Linux/amd64, Linux/arm64, Windows/amd64, and macOS/arm64. A queued or running
workflow is not evidence that binary assets have finished publishing.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x and Go 1.26.x are supported; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- mlib functions must not receive root-libc carriers, and root-libc functions
  must not receive mlib carriers.
- Interfaces and ABI details remain pre-1.0 and may change.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
agreement cannot relicense LLVM, musl, or other third-party code.
