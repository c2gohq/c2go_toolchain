> **候选版本：**本版本用于评估和兼容性测试，尚未签名，也未达到生产可用状态。

C2Go Toolchain `v0.20260802.0-rc.1` 修复了一个 AArch64 返回地址破坏
问题，该问题会导致生成的 Go 汇编在 Linux arm64 上崩溃。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260802.0-rc.1/RELEASE_NOTES/v0.20260802.0-rc.1.md)

## 相比 v0.20260801.0-rc.2 的变化

- AArch64 后端现在会在寄存器分配阶段为所有 c2go 模式函数保留
  link register（`LR`/`X30`）。
- LLVM 叶函数不再能把 `LR` 分配为临时寄存器。Go arm64 汇编器根据
  函数中是否存在调用来判定叶函数，并不会恢复叶函数的 link register；
  因此旧产物可能让 `RET` 跳转到临时数据。
- 实际崩溃在 c2go-libc 的大角度三角函数路径中复现：`sin` 调用
  `__rem_pio2_large`，而后者生成的叶函数把栈地址写入了 `R30`。
- 已重新生成 Darwin 和 Linux arm64 的 c2go-libc 汇编。生成脚本现在会
  拒绝任何显式 `R30` 分配，防止错误产物被提交或发布。
- 新增寄存器压力回归测试，可证明旧后端会分配 `R30`，修复后则会改用溢出
  栈槽。
- c2go-bind 和 c2go musl fork 与上一个候选版本相同。

## 打 tag 前的验证

- AArch64 c2go LLVM 代码生成测试 23/23 通过。
- 使用 Go 1.25.9 在 Darwin arm64 上执行 `go test ./...` 全部通过。
- Linux arm64 `TestSin` 在原生 arm64 容器中连续执行 100 次通过。
- c2go-libc 根包、`dl` 和 `selftest` 的测试二进制均在 Linux arm64 Debian
  容器中通过。
- 生成的 c2go-libc 汇编中，显式 `R30` 在 Linux arm64 上从 501 处降为
  0，在 Darwin arm64 上从 340 处降为 0。

打 tag 后的 release workflow 会重新构建并测试全部受支持的发布目标。

## 已知限制与许可证

- 仅支持 C，不支持 C++ 和 32 位目标。
- 仅支持 Go 1.25.x；Windows 的 POSIX 接口范围较小。
- C2Go 无法像 Go 编译器一样把发生逃逸的 C 栈局部变量提升到堆上；发布前必须把
  独立 `c2go-lto` 逃逸审计作为单独门禁。
- 接口和 ABI 细节仍处于 pre-1.0 阶段，后续可能修改。

`licenses/` 中的授权记录。商业协议不能重新许可 LLVM、musl 或其他第三方代码。
