# C2Go Toolchain v0.20260809.0-rc.3

This candidate supersedes `v0.20260809.0-rc.2`, whose native Windows runtime
gate failed before packaging. It retains the Linux ARM64 compiler corrections
from rc.2 and fixes the Windows managed-glob selftest portability defect.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.3/RELEASE_NOTES/v0.20260809.0-rc.3.zh-CN.md)

## Changes from v0.20260809.0-rc.2

- The managed `glob` GC/ownership fixture now normalizes the host-derived
  Windows `%TEMP%` path to forward slashes. Production `glob` keeps POSIX
  pattern semantics, including backslash escaping.
- Namespaced and unprefixed Windows selftest assembly was regenerated from the
  corrected fixture.
- A dedicated native Windows contract workflow now separates root libc, mlib,
  directory, glob, synchronization, stdio, regex, and search tests so failures
  are attributable before a release tag is created.

The AArch64 variadic ABI, split-GOT lowering, regenerated Linux/ARM64 artifacts,
and generator safety gates described in rc.2 are unchanged.

## Validation before tagging

- Native Windows/AMD64 passes every sharded contract job, including namespaced
  managed glob and the complete unprefixed mlib selftest.
- macOS/ARM64 passes all packages with `GOGC=1` and
  `GODEBUG=invalidptr=1` after regeneration.
- Windows/AMD64 cross-compiles and assembles every Go package locally.
- The locked component revisions and remote component tags pass the release
  snapshot verifier.

The tagged aggregate workflow must still complete before the draft and
downloadable assets are considered available.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x and Go 1.26.x are supported; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- mlib functions must not receive root-libc carriers, and root-libc functions
  must not receive mlib carriers.
- Interfaces and ABI details remain pre-1.0 and may change.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
agreement cannot relicense LLVM, musl, or other third-party code.
