# C2Go Toolchain v0.20260809.0-rc.5

本候选版本取代 `v0.20260809.0-rc.4`。rc.4 的 Windows SDK 验证器会错误地
编译有意不在 Windows 提供的 managed `ftw` 门面，因此无法完成已安装包验证。
rc.5 修正这一发布工具缺陷；组件代码与生成产物仍固定为 rc.4 的相同 revision。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.5/RELEASE_NOTES/v0.20260809.0-rc.5.md)

## 相比 v0.20260809.0-rc.4 的变化

- Windows SDK 验证现在会把 `<ftw.h>` 及其 managed 门面
  `<c2go/mlib/ftw.h>` 都视为有意不提供的头文件。Windows 没有对应的
  MinGW/CRT 功能面。
- 新增发布工具回归测试，确保这两个头只在 Windows 跳过，在其他平台仍参与
  头文件验证。
- 快速发布工具测试会在输入校验阶段运行，早于耗时的多平台 LLVM/Clang 构建。

rc.4 的 libc 跨宿主确定性修复、Windows managed `glob` 修复，以及 AArch64
ABI/lowering 修正均保持不变。

## 打标签前的验证

- 使用锁定的 c2go-clang revision 和 Windows 目标三元组在本机复现了原始
  头文件失败。
- 修正后，66 个受支持的 Windows 公共头均逐个通过 C2Go 语法检查；只排除
  7 个有意不提供的根层/managed 头。
- 两项发布工具回归测试全部通过。
- libc 完整重新生成仍保持幂等，并且 macOS/ARM64 宿主与干净
  Linux/AMD64 容器生成的二进制 diff 逐字节一致。
- macOS/ARM64 与 Linux/AMD64 原生环境通过 GC 压力下的全部 package；
  Linux/ARM64 与 Windows/AMD64 交叉编译通过。
- Windows/AMD64 原生环境通过全部 11 个分片 runtime contract job。
- 锁定的组件 revision 与远端组件标签通过 release snapshot verifier。

聚合标签触发的 workflow 仍须完整通过，之后才能认为 GitHub Release 草稿和
下载资产可用。

## 已知限制与许可

- 仅支持 C；不支持 C++ 和 32 位目标。
- 支持 Go 1.25.x 和 Go 1.26.x；Windows 的 POSIX 功能面较小。
- C2Go 不能把发生逃逸的 C 栈局部变量提升到堆上；发布时仍需单独运行
  `c2go-lto` 逃逸审计。
- mlib 函数不能接收 root libc carrier，root libc 函数也不能接收 mlib
  carrier。
- 接口和 ABI 仍处于 pre-1.0 阶段，后续可能调整。
