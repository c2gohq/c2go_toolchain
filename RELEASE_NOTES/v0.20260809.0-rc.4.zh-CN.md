# C2Go Toolchain v0.20260809.0-rc.4

本候选版本取代 `v0.20260809.0-rc.3`；后者的 Linux/AMD64 builder 在打包前
发现已提交汇编不能跨宿主机复现。rc.4 保留此前候选版本中的 Windows managed
`glob` 和 Linux ARM64 修正，并使 C2Go libc 生成结果不再依赖宿主 checkout
路径与宿主操作系统。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.4/RELEASE_NOTES/v0.20260809.0-rc.4.md)

## 相比 v0.20260809.0-rc.3 的变化

- libc 与 mlib 生成时会把源码根目录映射为稳定的相对路径，避免生成的自测中
  C `__FILE__` 值嵌入本机 checkout 路径。
- Darwin 生成现在固定 macOS 11 最低部署版本。未带版本的 Darwin target
  过去会在 Darwin 宿主上继承本机 macOS 版本，而 Linux 交叉生成时会选择另一
  默认值。
- 受影响的自测汇编已重新生成，不再包含工作站专属路径。

生产库汇编与 rc.3 相比没有其他变化。Windows managed `glob` 可移植性修复、
AArch64 可变参数 ABI 与拆分 GOT 修正，以及生成器安全门均继续保留。

## 打标签前的验证

- macOS/ARM64 上完整重新生成具备幂等性。
- 干净 Linux/AMD64 容器使用锁定的 c2go-clang 与 c2go-bind revision 生成的
  完整二进制 Git diff，与 macOS/ARM64 逐字节一致。
- macOS/ARM64 与 Linux/AMD64 原生环境在 `GOGC=1`、
  `GODEBUG=invalidptr=1` 下通过全部 package 测试。
- Linux/ARM64 与 Windows/AMD64 可交叉编译和汇编全部 Go package。
- Windows/AMD64 原生 runner 的全部 contract 分片通过，包括 namespaced
  managed glob 和完整的 unprefixed mlib 自测。
- 锁定的组件 revision 与远端组件标签通过 release snapshot verifier。

聚合标签触发的 workflow 仍须完整通过，之后才能认为 GitHub Release 草稿和
下载资产可用。

## 已知限制与许可

- 仅支持 C；不支持 C++ 和 32 位目标。
- 支持 Go 1.25.x 和 Go 1.26.x；Windows 的 POSIX 功能面较小。
- C2Go 不能把发生逃逸的 C 栈局部变量提升到堆上；发布时仍需单独运行
  `c2go-lto` 逃逸审计。
- mlib 函数不能接收 root libc carrier，root libc 函数也不能接收 mlib
  carrier。
- 接口和 ABI 仍处于 pre-1.0 阶段，后续可能调整。
