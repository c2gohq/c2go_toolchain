> It is unsigned and not production-ready.

C2Go Toolchain `v0.20260801.0-rc.2` makes the simple, unparameterized managed
region the default spelling for ordinary C2Go code while preserving explicit
world masks for advanced control.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260801.0-rc.2/RELEASE_NOTES/v0.20260801.0-rc.2.zh-CN.md)

## Changes from v0.20260801.0-rc.1

- `#pragma c2go managed push` now enables all managed defaults: function,
  pointer, and record (`C2GO_FUNC | C2GO_PTR | C2GO_RECORD`). This is the
  recommended form for most managed regions.
- `managed(N)` remains available for selective control. Its mask now accepts
  integer literals and macro-expanded terms joined with bitwise OR and
  parentheses, such as `managed(C2GO_PTR | C2GO_RECORD)`.
- Explicit masks are validated to the supported `0..7` range. Empty
  `managed()`, undefined identifiers, unsupported operators, and malformed OR
  expressions are rejected with pragma diagnostics.
- The public header, implementation comments, regression tests, and bilingual
  documentation now agree on the active function bit and the default spelling.
- The C2Go ABI epoch, Go compatibility window, c2go-bind, c2go-libc, and musl
  revisions are unchanged from rc.1.

## Recommended region syntax

```c
#include <c2go.h>

#pragma c2go managed push
struct Node {
    struct Node *next;
    long value;
};
#pragma c2go pop
```

Use an explicit symbolic mask only when one managed default must remain off:

```c
#pragma c2go managed(C2GO_PTR | C2GO_RECORD) push
/* declaration-only functions here remain native imports */
#pragma c2go pop
```

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x only; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- Interfaces and ABI details remain pre-1.0 and may change.
