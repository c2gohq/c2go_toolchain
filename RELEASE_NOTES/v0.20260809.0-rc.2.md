# C2Go Toolchain v0.20260809.0-rc.2

This candidate supersedes the incomplete `rc.1` packaging attempt. It retains
the managed-libc surface introduced by that candidate and fixes two Linux
ARM64 code-generation defects found by the native release runner.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.2/RELEASE_NOTES/v0.20260809.0-rc.2.zh-CN.md)

## Changes from v0.20260809.0-rc.1

- C2Go variadic functions now use the same single `void *` cursor
  representation on every AArch64 target. Linux no longer exposes the native
  five-field AAPCS `va_list` to generated Go declarations or stack maps.
- The AArch64 Plan 9 printer now preserves the symbol address when scheduling
  separates an ELF GOT `ADRP` from its companion `LDR`, including across a
  basic-block boundary. This prevents `runtime.writeBarrier` flag bytes from
  being interpreted as a pointer and dereferenced.
- Root libc and mlib Linux/ARM64 Go and assembly artifacts were regenerated
  with the corrected compiler.
- Both libc generators now reject the unsafe bare 64-bit
  `MOVD runtime·writeBarrier(SB)` form in ARM64 output, turning this failure
  mode into a release-time error.

All other managed-libc APIs and compatibility rules are unchanged from
`v0.20260809.0-rc.1`.

## Validation before tagging

- The focused clang variadic-ABI and split-GOT regressions pass.
- Root libc and mlib generation complete with the new ARM64 safety gate.
- Native Linux/ARM64 and macOS/ARM64 full package tests pass with `GOGC=1` and
  `GODEBUG=invalidptr=1`.
- Linux/AMD64 passes ten independent full-package test processes under Go
  1.26 with the same GC stress settings.
- Windows/AMD64 compiles and assembles every package; the tagged workflow is
  the native Windows runtime gate.

The workflow must complete before the draft and downloadable assets are
considered available.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x and Go 1.26.x are supported; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- mlib functions must not receive root-libc carriers, and root-libc functions
  must not receive mlib carriers.
- Interfaces and ABI details remain pre-1.0 and may change.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
agreement cannot relicense LLVM, musl, or other third-party code.
