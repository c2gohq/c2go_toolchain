> **候选版本：**本版本用于评估和兼容性测试，尚未签名，也未达到生产可用状态。

C2Go Toolchain `v0.20260809.0-rc.1` 首次在
`github.com/c2gohq/c2go_libc/mlib` 中提供较完整的 managed libc 接口。
转换后的 C 代码可以在精确扫描的 C record 中保存 Go managed pointer，而不必
再经由 root libc 包的进程级 handle table 保存这些对象。

[English release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.1/RELEASE_NOTES/v0.20260809.0-rc.1.md)

## 相比 v0.20260804.0-rc.1 的变化

- 新增带 `mlib_*` 命名空间的接口；对已经实现的 managed 函数簇，也可显式使用
  `C2GO_MLIB_UNPREFIXED` 替换源码中的标准函数名。
- 新增 managed semaphore、pthread 生命周期与同步对象；目录流、`scandir`、
  `glob`、`nftw`/`ftw`；搜索树、哈希表与队列；managed POSIX regex；以及
  managed `FILE` 接口，包括标准流、内存流、cookie 流、宽字符流、格式化 I/O
  与进程流。
- 新增由 GC 持有的 `strdup`、`strndup`、`wcsdup`、`asprintf`、
  `vasprintf`、`realpath` 和 `getcwd` 变体。
- 逻辑释放现在会清空 libc 自己持有的 managed root。若 C API 只能按值接收
  owning pointer，调用方在 close、destroy 或 release 后仍应把最后一个 owner
  显式置为 `NULL`。
- 无状态算法和 Go 状态核心继续复用；只有 allocator、record layout 或返回对象图
  不兼容的 C 代码才选择性生成 mlib 实例，不会把完整 musl 双编译。
- c2go-clang 现在会为导出的按值 C record 生成真实布局，Go 声明不再用零大小
  placeholder，从而保留正确的参数大小与位置。
- c2go-bind 现在能为生成的 libc 子包和汇编中直接引用的顶层 Go 包补齐 import。
- Release workflow 会在 Linux/amd64 使用锁定版本的 clang、c2go-lto 和
  c2go-bind 重新生成 root libc 与 mlib，并在提交的 `.go`/`.s` 发生任何差异时
  拒绝发布。

`mlib` 是选择性的 managed 接口，不是第二套完整 libc。当前刻意不提供 umbrella
header，请只包含实际使用的 `<c2go/mlib/*.h>`。普通 `malloc`、`realloc`、
`free` 不属于 mlib：包含指针的 managed record 必须使用带类型信息的
`gc_malloc`，只有完全不含指针的存储才能使用 `gc_malloc(NULL, size)`。
`iconv` 仍只在 root libc 提供，`lsearch`/`lfind` 也仍只适用于无指针元素。

## 打 tag 前的验证

- 使用本次锁定的 c2go-clang 与 c2go-bind，root libc 和 mlib 的五个发布目标均
  重新生成，结果与已提交产物完全一致。
- c2go-clang 的按值 record 重点回归测试通过。
- c2go-bind 全部测试通过。
- c2go-libc 全部包在 `GOGC=1`、`GODEBUG=invalidptr=1` 下通过；mlib 全部包
  还在 Darwin/arm64 上通过 Go race detector。

推送 tag 后，release workflow 会在 Linux/amd64、Linux/arm64、Windows/amd64
和 macOS/arm64 上重复原生 Go contract 与安装包验证。Workflow 仍在排队或运行
时，不能据此宣称二进制产物已经发布完成。

## 已知限制与许可证

- 仅支持 C，不支持 C++ 和 32 位目标。
- 支持 Go 1.25.x 和 Go 1.26.x；Windows 的 POSIX 接口范围较小。
- C2Go 无法像 Go 编译器一样把发生逃逸的 C 栈局部变量提升到堆上；发布前必须把
  独立 `c2go-lto` 逃逸审计作为单独门禁。
- mlib carrier 不能传给 root libc 函数，root libc carrier 也不能传给 mlib
  函数。
- 接口和 ABI 细节仍处于 pre-1.0 阶段，后续可能修改。
