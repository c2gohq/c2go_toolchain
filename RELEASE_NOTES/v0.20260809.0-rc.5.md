# C2Go Toolchain v0.20260809.0-rc.5

This candidate supersedes `v0.20260809.0-rc.4`. The rc.4 Windows SDK verifier
would incorrectly compile the deliberately unavailable managed `ftw` facade and
therefore could not complete installed-package validation. rc.5 corrects that
release-tooling defect; component code and generated artifacts remain pinned to
the rc.4 revisions.

[简体中文 release notes](https://github.com/c2gohq/c2go_toolchain/blob/v0.20260809.0-rc.5/RELEASE_NOTES/v0.20260809.0-rc.5.zh-CN.md)

## Changes from v0.20260809.0-rc.4

- Windows SDK verification now treats both `<ftw.h>` and its managed facade
  `<c2go/mlib/ftw.h>` as deliberately unavailable. Windows has no corresponding
  MinGW/CRT surface for either header.
- Release-tool regression tests verify that both headers are skipped only on
  Windows and remain part of header validation on other platforms.
- The fast release-tool tests run during input validation, before the expensive
  multi-platform LLVM/Clang builds begin.

The host-independent libc generation fix from rc.4, the Windows managed `glob`
fix, and the AArch64 ABI/lowering corrections are unchanged.

## Validation before tagging

- The original Windows header failure was reproduced locally with the locked
  c2go-clang revision and the Windows target triple.
- After the correction, all 66 supported public Windows headers pass individual
  C2Go syntax checks; only the seven deliberately unavailable root/managed
  headers are excluded.
- Both release-tool regression tests pass.
- Full libc regeneration remains idempotent and byte-identical between the
  macOS/ARM64 host and a clean Linux/AMD64 container.
- Native macOS/ARM64 and Linux/AMD64 pass all packages under GC stress, and
  Linux/ARM64 plus Windows/AMD64 cross-compilation passes.
- Native Windows/AMD64 passes all 11 sharded runtime contract jobs.
- The locked component revisions and remote component tags pass the release
  snapshot verifier.

The tagged aggregate workflow must still complete before the draft and
downloadable assets are considered available.

## Known limitations and licensing

- C only; C++ and 32-bit targets are not supported.
- Go 1.25.x and Go 1.26.x are supported; Windows has a smaller POSIX surface.
- C2Go cannot promote an escaping C stack local to the heap. Run the standalone
  `c2go-lto` escape audit as a separate release gate.
- mlib functions must not receive root-libc carriers, and root-libc functions
  must not receive mlib carriers.
- Interfaces and ABI details remain pre-1.0 and may change.

This aggregate contains multiple license boundaries. Preserve and review the
root and `licenses/` records before use or redistribution. A commercial
agreement cannot relicense LLVM, musl, or other third-party code.
